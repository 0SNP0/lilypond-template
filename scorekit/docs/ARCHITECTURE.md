# Разделение произведения и ScoreKit

**ScoreKit пока обычная папка в Git**, но она подготовлена к выделению
в самостоятельный репозиторий и подключению в виде сабмодуля
`scorekit/` к разным партитурам.

## Репозиторий произведения

`music/*.ily`, `music/playback-map.json`, `orchestra.ily`,
`score.ly`, `concert-score.ly`, `parts/*.ly` и `metadata.ily`
содержат музыку, инструментальный состав и метаданные.

`.github/workflows/build.yml` задаёт основные события GitHub;
`.github/workflows/pages.yml` — публикацию последнего релиза на Pages;
`site/index.html` — главную страницу именно этой партитуры.
`docs/` содержит редакционные сведения по произведению.

## Фреймворк ScoreKit

- `scripts/`: компиляция LilyPond, проверки, аудио/MP3/SVG-экспорт,
  оформление ZIP/PDF/Release.
- `actions/`: переиспользуемые шаги GitHub Actions.
- `lilypond/`: общие стили страниц и Git-версия в колонтитулах.
- `viewer/portal/`: статический HTML/JS просмотрщик одной партитуры.
- `viewer/build_site.py`: генерация структуры сайта из `site/`.
- `viewer/publish_latest.py`: последний GitHub Release → SVG/JSON/MP3
  на собственном Pages-сайте партитуры.
- `viewer/serve.py`: локальный запуск той же структуры сайта.
- `site-template/`: пример конфигурации сайта нового произведения.

Сайт не загружает ZIP напрямую из GitHub Releases в браузере (это
вызывало CORS). Вместо этого CI один раз распаковывает последний
релиз; в браузере все ресурсы доступны по URL того же домена.
Ни SVG, ни MP3 предыдущих релизов на Pages не хранятся. Выпуск релиза
запускает обновление Pages автоматически; PDF и архивные ZIP остаются
доступными в GitHub Releases.

## Будущий каталог

Если потребуется центральный каталог произведений, это будет
**отдельный независимый сайт**, содержащий только ссылки на Pages
проектов; переносить в него звуковые архивы или ScoreKit не нужно.

## Будущий сабмодуль

При выделении ScoreKit в отдельный репозиторий сохранить путь
`scorekit/`. Тогда исходники произведения и его Pages-сайт смогут
вызывать те же относительные пути. Для приватного сабмодуля
следует настроить права GitHub Actions на чтение.
