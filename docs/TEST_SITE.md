# Тестовый сайт внутри репозитория партитуры

Для обкатки той же архитектуры, что будет у отдельного будущего сайта,
этот репозиторий теперь владеет следующими файлами:

- `catalog.json` — один репозиторий, `0SNP0/lilypond-template`;
- `site/index.html` — главная страница;
- `.github/workflows/pages.yml` — проверка и публикация на Pages;
- `scorekit/` — общий движок (пока обычная папка, позже Git-сабмодуль).

Сборка сайта использует общую команду:

```bash
python3 scorekit/viewer/build_site.py --output _site
```

Локально:

```bash
python3 scorekit/viewer/serve.py
```

Адрес: `http://127.0.0.1:8000/`, просмотрщик:
`http://127.0.0.1:8000/viewer/`.

Для локальной проверки можно скачать `score-media-…` из Actions и указать
его как `SVG/JSON ZIP`. После открытия репозитория публикация релизов также
доступна через анонимный GitHub API. Прямой `fetch` ZIP из браузера нужно
отдельно проверить на совместимость с CORS.

GitHub Actions workflow `pages.yml` собирает и проверяет сайт после
изменений в **`main`**, загружает preview-артефакт и публикует Pages.
Репозиторий уже **public**. Для первой публикации включите
`Settings → Pages → Build and deployment → Source: GitHub Actions`
(это одноразовая настройка). Адрес сайта:
`https://0snp0.github.io/lilypond-template/`, просмотрщик —
`https://0snp0.github.io/lilypond-template/viewer/`.

В GitHub Releases уже опубликованы версии `v0.1` и `v0.1.1`.
Ссылка на главной странице открывает `v0.1.1`.
Напрямую читать ZIP из Releases браузеру иногда мешает CORS;
если это случится, остаётся локальный ZIP-режим или понадобится
отдавать ZIP по HTTPS с подходящими заголовками.

Сайт будет доступен публично после успешного деплоя Pages. В будущем файлы `site/`, `catalog.json`
и workflow просто переедут в отдельный репозиторий сайта; ScoreKit и
пути внутри него менять не нужно.
