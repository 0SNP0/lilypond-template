# Ensemble, Assemble — LilyPond orchestra template

[Build results](../../actions/workflows/build.yml) · [Releases](../../releases) · [Latest published materials](../../releases/latest)

## Для музыкантов

Откройте последнюю опубликованную версию в разделе Releases или скачайте предварительную сборку из **Actions → Build orchestra → Artifacts** для нужной ветки. Состав и количество доступных партий зависят исключительно от произведения в этой ветке, а не от предварительно настроенного списка.

Релиз и результат Actions включают общую партитуру, её концертную версию, отдельные партии в PDF, общий MIDI, MP3-дорожки и архивы для скачивания. Текущие названия произведения, состав, авторство и версия задаются в `metadata.ily` и в нотных исходниках.

> Партитуры, импортированные из MusicXML, обязательно сверяйте с оригиналом до передачи музыкантам: успешная компиляция не доказывает правильность артикуляции, оркестровки и разделения голосов.

## Для редактора партитуры

- `score.ly` — основная партитура, непосредственно открывается в Frescobaldi и VS Code.
- `concert-score.ly` — партитура в концертном строе.
- `orchestra.ily` — порядок инструментов, группы и транспозиции.
- `metadata.ily` — полное и короткое названия, авторы, оркестр, Git-версия на каждой странице.
- `music/global.ily` — общие темп, метр и репетиционные ориентиры.
- `music/*.ily` — ноты, разделённые по инструментам; комментарии с номерами тактов.
- `parts/*.ly` — самодостаточные исходники индивидуальных партий.
- `layout/*.ily` — формат A4, общий титульный блок, колонтитулы и размеры станков.

Папки `music` и `parts` могут содержать произвольное количество инструментов. У всех рабочих файлов стабильные имена без версии; номера релиза попадают только в экспортируемые файлы.

### Сборка

На Windows с Python и LilyPond в PATH:

```powershell
py -3 scripts/build.py build --audio
py -3 scripts/build.py package
```

На Linux аналогично используйте `python3`; для звуковых дорожек установите FluidSynth, FFmpeg и GM SoundFont. При наличии MIDI отдельной партии скрипт создаёт её MP3-дорожку. Без `--audio` компилируются только PDF и MIDI.

`python3 scripts/build.py readme` не требуется для нотной сборки; редактировать музыкальные метаданные следует только в `metadata.ily`. Режим `LILYPOND_EXPORT_VIEWER=1` включает дополнительный экспорт SVG и JSON для экспериментального просмотрщика; по умолчанию он не замедляет обычный выпуск.

### Принципы

Публикация и предпросмотр не изменяют Git-репозиторий. GitHub Actions имеют доступ **только на чтение** и никогда не коммитят результат сборки. Файлы результата размещаются в `dist/` и исключены из контроля версий.

Главный стандарт: всё, что лежит **вне `.ly` и `.ily`**, не должно зависеть от конкретного произведения, количества инструментов или их названий. Музыкальные особенности редактируются непосредственно в LilyPond.

Для партитур с несколькими музыкантами на стане используйте отдельные голосовые переменные и возможность формирования как совмещённых, так и раздельных партий. Не пытайтесь автоматически разделять два инструмента только по факту наличия аккорда: музыкальный смысл нужно сверять с первоисточником.
