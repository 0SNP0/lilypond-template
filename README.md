## Партитура и партии

Вальс Георгия Свиридова из «Метели» для **Ensemble, Assemble**. PDF отдельных партий, общая партитура в транспонированном и концертном строе, а также звуковые дорожки доступны в выпусках проекта.

**[Скачать последнюю опубликованную партитуру и партии](https://github.com/0SNP0/lilypond-template/releases/latest)** · [Все версии](https://github.com/0SNP0/lilypond-template/releases).

В каждом релизе: PDF полной и концертной партитур и всех имеющихся партий, два архива PDF и аудио и отдельный архив SVG с просмотрщиком и данными синхронизации. Отпечатки партий отдельно входят в архив PDF. В именах всех готовых файлов — короткое название произведения и версия Git. Аудиоархив содержит общий MP3 (с нормализацией громкости до −16 LUFS и ограничением пиков −1,5 dBTP), 21 отдельную инструментальную MP3-дорожку и MIDI. Дополнительно GitHub Actions хранит артефакты новых сборок на ограниченный срок.

## Для аранжировщика

**[Открыть общую партитуру](score.ly)** — этот файл самодостаточен для предпросмотра в Frescobaldi, VS Code (LilyPond) и нативном LilyPond на Windows. Достаточно открыть `score.ly` и запустить компиляцию; предварительно запускать Python не требуется. **[Открыть концертную партитуру](concert-score.ly)**.

**Флейты I–II, кларнеты I–II, трубы I–II и тромбоны I–II** остаются на одном стане, но по умолчанию пишутся **двумя раздельными голосами** — даже когда совпадает отдельная нота. Чтобы объединить штили и вывести `a2`, аранжировщик помечает **целиком совпадающий такт** командой `\partCombineUnisono` в исходнике первого музыканта. Перед следующим различающимся тактом возвращает `\partCombineApart`. Таким образом, нет случайного `a2` посреди такта; ручное управление остаётся непосредственно в LilyPond. См. [инструкцию с примером](docs/PART_COMBINING.md). При печати доступны 21 индивидуальная и четыре совмещённые партии, причём MIDI и MP3 остаются только индивидуальными (21 дорожка, без дублирования при сведении). В **концертной партитуре** бас-кларнет и тенор-саксофон используют `treble_8`, а контрабасы — `bass_8`, без изменения звучащей высоты.\n\nСовпадающие по началу и длительности паузы на четырёх совмещённых станах автоматически печатаются одной паузой благодаря `Merge_rests_engraver`, **даже когда ноты остаются в отдельных голосах**. Совпавшие одиночные ноты по-прежнему не дают `a2`. Для быстрой навигации в `music/*.ily` принято ставить комментарии с номерами тактов каждые четыре такта (`% Bars 1–4`, `% Bars 5–8`); см. [соглашения об исходниках](docs/CODE_STYLE.md).

Музыка находится в `music/*.ily`. **[Порядок инструментов](orchestra.ily)** задаётся ровно там: по секциям и в желаемой последовательности, а не номерами в именах файлов. Отдельные файлы `parts/*.ly` открываются точно так же. Все названия инструментов английские. При изменении состава добавь/удали соответствующий `parts/name.ly`, `music/name.ily` и нотоносец в `orchestra.ily`.

Короткий идентификатор `workFileSlug` из `metadata.ily` используется только для названий экспортируемых файлов: например, `orchestral-sketch-score-v0.3.pdf`, `orchestral-sketch-alto-saxophone-v0.3.pdf`, `orchestral-sketch-concert-score-v0.3.pdf`. Полное название `workTitle` остаётся на титуле. Названия исходных `.ly` не содержат версии и не меняются от выпуска к выпуску. Для струнных используются названия секций во множественном числе: `Violins`, `Violas`, `Violoncellos`, `Contrabasses`.

Сведения о произведении меняются в **[metadata.ily](metadata.ily)**. Они используются самой партитурой и синхронизируются в README командой `python scripts/build.py readme`. Поле `ensembleName` — название оркестра, **не исполнитель и не аранжировщик**.

### Экспорт SVG, синхронизация и отпечатки

Сборка с `--audio` дополнительно экспортирует **27 SVG-представлений** (две партитуры, 21 индивидуальная и 4 совмещённые партии), `dist/viewer/timeline.json` и `dist/viewer/manifest.json`. Каждый такт получает сквозной логический идентификатор вида `measure-0001`, общий для всех видов нот. Временная шкала берётся из MIDI и учитывает события изменения темпа; SVG остаётся в оригинальной LilyPond-вёрстке.

Отпечатки **не относятся к воспроизведению** и поэтому вынесены в самостоятельный `dist/print-manifest.json` (также внутри PDF-архива): `music_hash` отражает нормализованные MIDI-события, `print_hash` — SVG-оттиск с маскированием текстовой Git-версии. Это предварительные значения: **очереди печати и автоматического признания старых партий совместимыми пока нет**. В манифесте также перечислены реально найденные SVG-якоря; если LilyPond не даёт устойчивую привязку, координаты не выдумываются. В архив SVG входит **простой статический просмотрщик** (`viewer/index.html`), HTML/SVG/JSON, общий MP3 и **21 инструментальный MP3**. Для просмотра достаточно распаковать архив и запустить из его корня `python -m http.server 8000`, затем открыть `http://localhost:8000/viewer/`. В браузере можно **независимо** выбирать нотное представление и звучащую дорожку (весь оркестр либо любой из 21 инструментов), сохраняя позицию и скорость при переключении. Курсор ориентируется по координатам SVG-якорей тактов. Это экспериментальный прототип: не поддерживает точную подсветку каждой ноты, раскрытие реприз и автоматическую компенсацию задержки MP3.

### Сборка Windows (без WSL)

Установить Python 3, Git for Windows и нативный LilyPond, доступные в PATH:

```powershell
py -3 scripts/build.py build
```

Для MP3 дополнительно нужны FluidSynth, FFmpeg и SoundFont:

```powershell
py -3 scripts/build.py build --audio --soundfont "C:\SoundFonts\MS_Basic.sf3"
py -3 scripts/build.py package
```

На Linux команды те же, только `python3`. Файлы результата находятся в игнорируемой папке `dist/`. `python scripts/build.py clean` удаляет сгенерированные файлы.

### Оформление

Все страницы — **A4**. В отдельных партиях поля 15 мм; у общей партитуры поля 3 мм слева/справа и 4 мм сверху/снизу, чтобы использовать всю площадь A4. Отдельные партии имеют увеличенный нотоносец, незаполненная часть страницы не растягивается. Название инструмента печатается в верхнем колонтитуле, но **не** слева от нотоносцев партии. При необходимости конкретную партию можно дополнить локальной директивой `\paper { page-count = #2 }`, следя за читаемостью.

Общая партитура автоматически выбирает масштаб исходя из числа реальных нотоносцев (включая пары станков у фортепиано и аккордеона), а сборка дополнительно уменьшает его, если LilyPond предупреждает о переполнении. При этом заголовки, подписи инструментов, сведения об авторах и колонтитулы используют **абсолютные размеры текста**, независимые от масштаба нотоносцев. Заголовок оформлен одинаково в партитуре и партиях: книжный шрифт TeX Gyre Pagella, подзаголовок под названием и отдельная строка для авторских сведений без наложений. На первой странице название не повторяется в верхнем колонтитуле; на последующих оно показывается. Версия остаётся по центру нижнего колонтитула на каждой странице. В колонтитуле **каждой страницы** печатается версия Git: в CI она берётся из текущего коммита или тега, при прямом предпросмотре из репозитория через Git.

### Версии

Версия печатается **как Git её сформировал**: например, `v1.2.0`, `v1.2.0-3-gabcdef12`, `abcdef12`, `abcdef12-dirty`. Никакая дополнительная `V` перед хешем не добавляется. При запуске прямо из Frescobaldi/VS Code версия определяется по Git, поэтому она не зависит от предварительного запуска Python. Если Git недоступен, печатается `unversioned`. Релизы собираются из чистых тегированных коммитов и содержат `build-info.json`.

### Тесты и качество

Вместо искусственных unit-тестов структура проверяется во время настоящей сборки: LilyPond должен успешно скомпилировать **все** партии, MIDI и PDF, а PDF должны быть A4 (проверяется `pypdf`, если установлен). Сборка останавливается при переполнении партитуры. Workflow запускается на push и Pull Request, а по тегу `v*` создаёт релиз или загружает файлы в уже созданный через GitHub релиз. README всегда ссылается на `/releases/latest` и **никогда не изменяется вслед за очередным выпуском**. В CI устанавливается последний стабильный LilyPond из официального Linux-пакета, а не устаревшая версия из Ubuntu apt.
