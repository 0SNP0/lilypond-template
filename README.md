## Партитура и партии

Короткий оркестровый этюд для **Ensemble, Assemble**. PDF отдельных партий, общая партитура в транспонированном и концертном строе, а также звуковые дорожки доступны в выпусках проекта.

**[Скачать последнюю опубликованную партитуру и партии](https://github.com/0SNP0/lilypond-template/releases/latest)** · [Все версии](https://github.com/0SNP0/lilypond-template/releases).

В каждом релизе: **27 PDF-файлов** (две общие партитуры, 21 индивидуальная партия и четыре совмещённые партии) и два архива PDF и аудио. В именах всех готовых файлов — короткое название произведения и версия Git. Аудиоархив содержит общий MP3, 21 отдельную инструментальную MP3-дорожку и MIDI. Дополнительно GitHub Actions хранит артефакты новых сборок на ограниченный срок.

## Для аранжировщика

**[Открыть общую партитуру](score.ly)** — этот файл самодостаточен для предпросмотра в Frescobaldi, VS Code (LilyPond) и нативном LilyPond на Windows. Достаточно открыть `score.ly` и запустить компиляцию; предварительно запускать Python не требуется. **[Открыть концертную партитуру](concert-score.ly)**.

**Флейты I–II, кларнеты I–II, трубы I–II и тромбоны I–II** показываются в общих партитурах попарно на одном стане через `\partCombine`: в унисон нотам соответствует **одна головка и один штиль** с пометкой `a2`, а при расхождении голосов используются раздельные штили. Настройка `#'(0 . 0)` не объединяет разные высоты в аккорды. При печати доступны оба варианта: индивидуальные партии каждого музыканта (`parts/*.ly`) и четыре совмещённых листа (`parts/combined/*.ly`). Совмещённые листы лежат в `parts/combined/` внутри PDF-архива; MIDI и MP3 по-прежнему создаются **по одному на музыканта** (21 дорожка), без дублирования при сведении. Порядок инструментов в партитуре настраивается в `orchestra.ily`, объединение голосов — в `music/paired.ily`. В **концертной партитуре** бас-кларнет и тенор-саксофон используют `treble_8`, а контрабасы — `bass_8`, чтобы отображать низкую тесситуру на октаву выше при неизменной звучащей высоте. В транспонированной партитуре и отдельных партиях обычные ключи сохранены.

Музыка находится в `music/*.ily`. **[Порядок инструментов](orchestra.ily)** задаётся ровно там: по секциям и в желаемой последовательности, а не номерами в именах файлов. Отдельные файлы `parts/*.ly` открываются точно так же. Все названия инструментов английские. При изменении состава добавь/удали соответствующий `parts/name.ly`, `music/name.ily` и нотоносец в `orchestra.ily`.

Короткий идентификатор `workFileSlug` из `metadata.ily` используется только для названий экспортируемых файлов: например, `orchestral-sketch-v0.3.pdf`, `orchestral-sketch-alto-saxophone-v0.3.pdf`, `orchestral-sketch-concert-score-v0.3.pdf`. Полное название `workTitle` остаётся на титуле. Названия исходных `.ly` не содержат версии и не меняются от выпуска к выпуску. Для струнных используются названия секций во множественном числе: `Violins`, `Violas`, `Violoncellos`, `Contrabasses`.

Сведения о произведении меняются в **[metadata.ily](metadata.ily)**. Они используются самой партитурой и синхронизируются в README командой `python scripts/build.py readme`. Поле `ensembleName` — название оркестра, **не исполнитель и не аранжировщик**.

### Сборка Windows (без WSL)

Установить Python 3, Git for Windows и нативный LilyPond, доступные в PATH:

```powershell
py -3 scripts/build.py build
```

Для MP3 дополнительно нужны FluidSynth, FFmpeg и SoundFont:

```powershell
py -3 scripts/build.py build --audio --soundfont "C:\SoundFonts\MS_Basic.sf3"
py -3 scripts/build.py package
```

На Linux команды те же, только `python3`. Файлы результата находятся в игнорируемой папке `dist/`. `python scripts/build.py clean` удаляет сгенерированные файлы.

### Оформление

Все страницы — **A4**. В отдельных партиях поля 15 мм; у общей партитуры поля 3 мм слева/справа и 4 мм сверху/снизу, чтобы использовать всю площадь A4. Отдельные партии имеют увеличенный нотоносец, незаполненная часть страницы не растягивается. Название инструмента печатается в верхнем колонтитуле, но **не** слева от нотоносцев партии. При необходимости конкретную партию можно дополнить локальной директивой `\paper { page-count = #2 }`, следя за читаемостью.

Общая партитура автоматически выбирает масштаб исходя из числа реальных нотоносцев (включая пары станков у фортепиано и аккордеона), а сборка дополнительно уменьшает его, если LilyPond предупреждает о переполнении. При этом заголовки, подписи инструментов, сведения об авторах и колонтитулы используют **абсолютные размеры текста**, независимые от масштаба нотоносцев. Заголовок оформлен одинаково в партитуре и партиях: книжный шрифт TeX Gyre Pagella, подзаголовок под названием и отдельная строка для авторских сведений без наложений. На первой странице название не повторяется в верхнем колонтитуле; на последующих оно показывается. Версия остаётся по центру нижнего колонтитула на каждой странице. В колонтитуле **каждой страницы** печатается версия Git: в CI она берётся из текущего коммита или тега, при прямом предпросмотре из репозитория через Git.

### Версии

Версия печатается **как Git её сформировал**: например, `v1.2.0`, `v1.2.0-3-gabcdef12`, `abcdef12`, `abcdef12-dirty`. Никакая дополнительная `V` перед хешем не добавляется. При запуске прямо из Frescobaldi/VS Code версия определяется по Git, поэтому она не зависит от предварительного запуска Python. Если Git недоступен, печатается `unversioned`. Релизы собираются из чистых тегированных коммитов и содержат `build-info.json`.

### Тесты и качество

Вместо искусственных unit-тестов структура проверяется во время настоящей сборки: LilyPond должен успешно скомпилировать **все** партии, MIDI и PDF, а PDF должны быть A4 (проверяется `pypdf`, если установлен). Сборка останавливается при переполнении партитуры. Workflow запускается на push и Pull Request, а по тегу `v*` создаёт релиз или загружает файлы в уже созданный через GitHub релиз. README всегда ссылается на `/releases/latest` и **никогда не изменяется вслед за очередным выпуском**. В CI устанавливается последний стабильный LilyPond из официального Linux-пакета, а не устаревшая версия из Ubuntu apt.
